# 路线

对应 [game-design.md](game-design.md) 第 13 节首版范围。每项都标了要动哪里。

## 已完成：纵向切片（2026-11-02）

野外台地地形 → 远处可见的地标塔 → 按 E 进城 → 笔刷修复 / 涂鸦表面 → 退出重进颜色还在。

## 已完成：颜料循环（2026-11-02）

野外颜料点（4 种，按群系）→ 彩色颜料 + 墨，首采解锁颜色；城内墨渍 → 墨；画室提炼 墨 → 通用颜料。一座城自己的墨渍约够修复它的 30%，其余来自野外，以后加上敌人掉墨。数值在 `tuning.ts` 的 `economy`。

## 下一步（建议顺序）

1. **区块状态机 + 墨潮**：城市每区块的 抽色 / 清理 / 有色 / 繁荣 状态；墨潮是一个系统，按时间产出 `drain` 补丁
2. **墨污敌人与战斗**：从 doodle-game 移植武器（作为 `Tool`）和敌人 AI（作为系统）。敌人 AI 需要导航网格，移植 `nav.js`；敌人掉墨走已有的 `grant` 或新补丁
3. **繁荣街区产出**：画室按游戏时钟（`state.clock`）定时产出通用颜料
4. **教学城**：固定模板的 3×3 小城，出生点
5. **纸飞机**：一个 `Tool`，修改玩家下落速度
6. **AI 风格**：本地服务调用模型，给城市起名、配色、写居民诉求；结果作为"覆盖层"存档，失败用程序默认值
7. **多人**：房主权威，补丁同步。`WorldStore` 换成本地服务实现

## 已知限制

- 物理只有轴对齐盒子：道路只直角转弯，建筑不能斜放
- 存档在浏览器 localStorage，换浏览器或清数据会丢；多人前要换成本地服务
- 城市生成约 30 ms，进城时同步执行；城市变大后要挪到 Worker
- 树和草是合并网格，不是实例化；植被密度加大后要改 `InstancedMesh`（材质已支持）
