# 四季与天气设计

一句话：**四季和天气都是 `(种子, 世界时钟, 坐标)` 的纯函数。** 不存档、不同步，服务器和每个客户端各算各的，结果一致。和昼夜（`engine/render/daylight.ts`）一样，第一版只管画面和声音，玩法不读它。

在 [game-design.md](game-design.md) 里属于"探索"：远处压过来的雨云、山顶的雪线、秋天整片变黄的林子，都是"看得见"的目标和变化。

## 1. 分层

```text
世界时钟 state.clock
  └─► 日历 calendarAt(clock)          第几天、几点、年相位、季节混合        world/climate/calendar.ts
        ├─► 太阳轨迹（赤纬）            日长、正午高度                        engine/render/daylight.ts
        ├─► 季节外观（关键帧插值）      植被颜色、花、落叶、基础积雪          content/seasons.ts
        └─► 天气 weatherAt(clock, x, z) 云、降水、风、气温、雾、湿、雷        world/climate/weather.ts
              └─► 大气系统按玩家位置采样、缓动 ─► 渲染器 uniform、粒子、声音   systems/atmosphere/
```

- `world/climate/` 不用 Three.js，Node 可测；以后服务器要让天气影响玩法，直接调同一个函数。
- 遵守 `world/` 的约定：不用 `Math.random`，噪声用 `world/math/noise.ts` 的 `createNoise2D(seed)`，随机事件用 `hashAt`。
- 数值放 `content/tuning.ts` 的 `season` 和 `weather` 两节，季节关键帧放 `content/seasons.ts`。

## 2. 日历

| 量       | 算法                                                         | 初值                                                                     |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 一天     | `TUNING.day.length` 秒（已有）                               | 1440 秒（24 分钟）                                                       |
| 一季     | `TUNING.season.days` 天                                      | 7 天，一年 28 天，约 11 小时游戏                                         |
| 年相位   | `(天数 + 小时/24) / 一年天数`，取小数，0..1 连续             | 0 = 立春；春分、夏至、秋分、冬至在每季正中（0.125、0.375……），和节气一样 |
| 新世界   | `TUNING.season.startDay`                                     | 春第 3 天（花开得正好）                                                  |
| 季节混合 | 关键帧放在每季正中（0.125、0.375、0.625、0.875），smoothstep | 季节交替时是几天的渐变，不是一刀切                                       |

现在 `atmosphere.ts` 自己算小时；改成都从 `calendarAt` 取，日历只在一个地方算。

## 3. 太阳轨迹

按纬度 35°（温带，四季分明）算：

```text
赤纬    δ = 23.44° × sin(2π × (年相位 − 0.125))   夏至在夏季正中，和气温的峰值对齐
正午高度 = 90° − 35° + δ                     夏至约 78°，冬至约 32°
日长    = 2 × acos(−tan35° × tanδ) / 15°     夏至约 14.4 小时，冬至约 9.6 小时
```

`daylightAt(hour)` 改成 `daylightAt(hour, declination)`：

- 先把实际时刻按当天的日出、日落线性映射到"标准时刻"（日出 → 6 点，日落 → 18 点），再查现有的颜色关键帧。这样夏天的金色傍晚自然推迟，冬天天黑得早，关键帧一个都不用改。
- `arc()` 的最高点按正午高度缩放。冬天影子长，夏天影子短。
- 加测试：春分日长 12 小时；夏至日长 > 14 小时；冬至正午高度 < 35°。

## 4. 季节外观

`content/seasons.ts` 里四个关键帧，每帧一组外观参数：

| 参数       | 春            | 夏       | 秋               | 冬                   |
| ---------- | ------------- | -------- | ---------------- | -------------------- |
| 草色       | 嫩黄绿        | 浓绿     | 黄褐             | 枯褐                 |
| 阔叶树冠色 | 嫩绿 + 少量花 | 深绿     | 黄、橙、红       | 枯褐（树冠不缩小）   |
| 针叶树     | 不变          | 不变     | 不变             | 不变（冬天唯一的绿） |
| 野花密度   | 1.0           | 0.6      | 0.2              | 0                    |
| 落花落叶   | 樱花瓣 0.5    | 0        | 红黄落叶 1.0     | 0                    |
| 降水倾向   | 偏多（春雨）  | 阵雨、雷 | 偏少（秋高气爽） | 偏多（下雪）         |
| 盛行风     | 东南          | 南       | 西北             | 北                   |

**怎么换色（已定）**：不重建网格，也不改 `ink-material`，在后处理里换。G-buffer 里存的是调色板编号，后处理本来就按编号查颜色、也知道世界坐标，所以：

- 调色板颜色加一个可选的 `season` 类：`meadow`（草地、草叶：`grass`、`forest`、`sprout`）或 `leaf`（阔叶树冠：`leaf`、`canopy`）。杉树用 `cedar`，没有类，四季常绿。可涂的 `翠绿` 不加类，墙和涂鸦不会跟着变色。
- 着色器把有类的颜色朝当季的 `rgb` 混 `amount`，**保留原色的大部分明度**：林子还是比草地暗，秋天林子是深红、草原上的树是亮黄。
- **一片一片错开变色**：季节相位按世界坐标的低频噪声偏移 ±`TUNING.season.stagger`（0.05，约一天半），林子是一片一片黄进去的，不是同一帧全变。
- **秋天红黄相间、春天点缀樱花**：`alt` 颜色按另一层噪声分给 `altShare` 比例的地方（秋天 45% 红，春天 18% 粉）。
- 冬天阔叶树冠是枯枝的灰褐色；树冠缩小要重建网格，先不做。

**积雪**：`world/climate/temperature.ts` 给日均气温（年均 12°C ± 13°C，每米 −0.4°C），积雪 = `smoothstep(1, −3, 气温)`。后处理用同样的数按每个像素的高度算，再乘朝上程度和噪声：山顶春秋白、盛夏化完，平地深冬一半是雪。

## 5. 天气

### 5.1 输出

```ts
interface Weather {
  cloud: number; // 云量 0..1
  precip: number; // 降水强度 0..1
  snow: number; // 降水里雪的比例 0..1（由气温推出）
  wind: [number, number]; // 风向量，米/秒（盛行风 + 阵风）
  temp: number; // 气温 °C
  fog: number; // 雾 0..1
  wetness: number; // 地面湿度 0..1（最近下过雨）
  snowCover: number; // 地面积雪 0..1
  thunder: number; // 雷暴强度 0..1
}
```

天气不是"晴 / 雨 / 雪"这种枚举，而是这组连续参数；"下雪""雷阵雨"都是从参数推出来的。大气系统每 0.25 秒在玩家位置采样一次，每个参数朝采样值缓动，所以没有任何突变。

### 5.2 气温

```text
气温 = 年均 12°C
     + 13 × sin(2π × (年相位 − 0.125))      季节：仲夏 +13，深冬 −13
     + 4  × sin(2π × (小时 − 9) / 24)        昼夜：15 点最暖，3 点最冷
     − 0.4 × 地面高度（米）                  山上冷：36 米的山顶比平地冷约 14°C
     + 群系修正（湖河 +1，森林 −1）
     + 3 × 低频噪声(时间)                    暖冬、倒春寒
```

山高是游戏尺度（平地 0–10 米，山峰到 36 米），所以递减率比真实的 6.5°C/km 大得多；目标是山顶春秋积雪、盛夏化完，平地只在深冬偶尔下雪。

### 5.3 云和降水：随风漂移的噪声场

```text
D      = 盛行风对时间的积分（空气从开局起被吹走了多远）
(u, v)   = (x, z) − D                          整片云场顺风平移
(u', v') = (x, z) − 1.6 × 转 1 弧度(D)          第二层更快、换个方向漂
湿度   = 0.6 × fbm(A, u/1500, v/1500, 2 层) + 0.4 × fbm(B, u'/900, v'/900, 2 层)
       + 季节的 wet + 0.15 × 群系湿度（generator 已有的 moisture）
云量   = smoothstep(−0.15, 0.10, 湿度)            阴满了才开始下雨，所以有不下雨的阴天
降水   = smoothstep(0.13, 0.45, 湿度)
雪比例 = smoothstep(2, −1, 气温)
```

- 两层不同方向漂移的噪声相互叠加，雨云会在路上长大、消散，不是一张固定的图在平移。
- **D 是精确积分**：盛行风随季节转向，如果用"今天的风 × 总时间"，世界越老云飘得越快。所以开局时把一整年的风积分成一张 512 格的表，D = 整年数 × 一年的位移 + 查表。
- 云场平移速度约 3–5 米/秒，一片 1 公里的雨区大约 4 分钟（游戏里 4 小时）扫过去；最长一场雨约 15 分钟。
- 抽样一年 40 个地点的结果（阈值就是按这个调的）：

  | 季节 | 下雨 | 下雪 | 雷暴 | 阴天 | 晴天 |
  | ---- | ---- | ---- | ---- | ---- | ---- |
  | 春   | 25%  | 4%   | 1%   | 48%  | 41%  |
  | 夏   | 28%  | 0    | 8%   | 51%  | 34%  |
  | 秋   | 14%  | 0.3% | 0.5% | 33%  | 52%  |
  | 冬   | 14%  | 16%  | 0    | 52%  | 33%  |

  全年约 25% 的时间有降水（第一年的春天少一些：新世界第一天总是晴的）。阴天 = 云量 > 0.8，晴天 = 云量 < 0.2。单次 `weatherAt`（含 16 次回看）约 0.01 毫秒。

- 雨是**有位置的**：站在山坡上能看到远处一块地方在下雨，走过去会淋到。

### 5.4 雷、雾、风

- **雷暴**：`thunder = smoothstep(0.55, 1, 降水) × smoothstep(19, 27, 气温)`，所以基本只有夏天下午的大雨会打雷，晚春和初秋热的几天偶尔有。坡度放宽是为了不在大雨边缘一秒内跳起来。
- **闪电是确定的**：把时间切成 1 秒一格、空间切成 300 米一格，`hashAt(seed, 'bolt', 秒, 格x, 格z) < 雷暴强度 × 0.15` 的格子这一秒落一道闪电，落点也由哈希给出。所有客户端在同一时刻看到同一道闪电。
- **雾**：湿度高、风小、4–8 点、靠近水时起雾，太阳升高后散去；另加"雨后雾"：湿度高且降水刚停。
- **风**：盛行风（季节关键帧）× 大风天 × (1 + 0.5 × 阵风噪声(时间)) + 降水 × 6 米/秒。大风天是一层以一天半为周期的噪声，约四分之一的日子盛行风最多加强到 2.2 倍，不管下不下雨。驱动草和树冠的摆动、云和云影的漂移、雨雪和落叶、风声。

- **彩虹**：`rainbow = 过去 1–5 分钟里降过雨（≥ 0.5） × 现在几乎不下 × 云量在 0.92 以下 × 气温 0 °C 以上`。能不能看到还要看太阳：渲染时乘上太阳高度在地平线上、42° 以下。
- **霜**：`frost = smoothstep(3, −1, 气温) × 晴 × 风小 × 没有积雪 × 不在下`。气温带着昼夜项，所以夜里结、上午化。

### 5.5 有"记忆"的量：湿度和积雪

雨停以后地面还要湿一阵，这本来要存状态。为了保持纯函数，**回看过去**：

```text
湿度 = max over k=0..7 of  降水(时间 − k × 75 秒) × 0.8^k     回看 10 分钟
积雪 = max(smoothstep(1, −3, 日均气温), 回看过去 20 分钟的降雪量)
```

积雪用**日均气温**（去掉昼夜项），不然每天下午都化一次。每秒算一次，16 次 `weatherAt` 调用，开销可以忽略。

### 5.6 城市副本

城市是另一个场景。城里的天气等于野外这座城入口塔楼位置的天气，所以进城前在下雨，进城以后也在下雨。墨潮的 `gloom` 是后处理，叠在天气之上：墨潮来时雨照下，只是整个画面褪成黑白。

## 7. 玩法（第二阶段，单独决定）

第一版不做。以后每一条都要先回答设计稿第 1.1 节的问题：它让探索、PK 或打击感变好了吗？候选：

| 候选                                           | 对谁有好处           | 代价                           |
| ---------------------------------------------- | -------------------- | ------------------------------ |
| 大雾、暴雨缩短视距                             | PK（伏击）、探索     | 墨怪的感知距离也要跟着缩       |
| 雪地留脚印                                     | PK（追踪）           | 贴花系统，联机要同步脚印       |
| 雨水冲淡墨：雨中墨怪掉的墨变少，颜料点恢复变快 | 探索（什么时候出门） | 墨的经济要重新算               |
| 冬天水面结冰，能走过去                         | 探索（季节性捷径）   | 物理里加一种"冰面"，寻路要知道 |

因为天气是纯函数，服务器判定这些规则时直接调 `weatherAt`，不需要额外同步。

## 8. 联机

- 天气只依赖种子和世界时钟。服务器是时钟的权威（[game-design.md](game-design.md) 7.2），时钟本来就要随快照下发，所以天气**零额外带宽**。
- 闪电由哈希决定，所有人同时看到同一道。
- 以后要做剧情或活动的"强制天气"，加一条存档里的覆盖记录（起止时间 + 参数），`weatherAt` 先查覆盖再算噪声；仍然走补丁。

## 9. 调试

调试面板（`systems/debug/debug-panel.ts`）加：时间倍速（×1 / ×60 / ×600）、跳到某季、锁定天气参数（覆盖 `Weather` 的任意字段）。只影响画面，不写存档。

## 10. 测试

`tests/calendar.test.ts`、`tests/seasons.test.ts`、`tests/weather.test.ts`、`tests/daylight.test.ts`：

- **确定性**：同种子、同时间、同坐标，天气和闪电完全相同；换种子不同。
- **连续性**：时间差 1 秒、坐标差 1 米，各参数变化都小于 0.1，世界玩了好几年以后也一样。
- **统计**：在一年里均匀采样，检查：
  - 全年降水占比在 15%–35%；
  - 冬天会下雪，夏天不会；秋天最干；
  - 雷暴基本只在夏天，冬天没有；
  - 山顶春秋有积雪，盛夏没有；平地只在深冬。
- **雨后**：雨停一分钟地面还湿，十分钟后变干。
- **太阳**：春分日长 12 小时，夏至 > 14 小时，冬至正午高度 < 35°。

## 13. 开放问题

- 一年 28 天，玩家很少一次玩到一整年。要不要让季节跟真实日期走（像《动物森友会》），还是保留游戏时钟（离线不过季，和墨潮、颜料恢复一样）？现在按游戏时钟设计。
- 越灰的地方是否天气越阴沉：画面上和"灰"的主题很配，但会和墨潮的 `gloom` 抢表现。
- 城市副本恢复全城时，要不要强制雨过天晴、出彩虹（现在已有彩虹粒子特效）。
