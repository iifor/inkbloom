# 世界生成设计

两种生成器，对应 [game-design-v2.md](game-design-v2.md) 的两层世界：

|      | 野外                                        | 城市副本                             |
| ---- | ------------------------------------------- | ------------------------------------ |
| 范围 | 无限                                        | 有限，默认 5×5 区块                  |
| 原则 | 任意区块独立可算，只依赖 `(种子, 层, 坐标)` | 创建时一次全局求解，整体落盘         |
| 算法 | 分层噪声 + 大格子哈希 + 模板                | 道路生长 + 街块切分 + 模板 / AI 填充 |
| AI   | 不用                                        | 风格、名字、诉求；失败有模板兜底     |
| 存盘 | 不存地形，只存玩家改变                      | 全存                                 |

两者的噪声和哈希实现放在 `world/` 层，浏览器和 Node 结果完全一致，有测试。区块仍为 128 米见方。

## 1. 野外

### 1.1 分层

参考 Minecraft：几层全局连续函数叠加，每层只看坐标和种子，相邻区块查同一个函数所以边界天然连续。

| 层   | 决定什么                         | 算法                         |
| ---- | -------------------------------- | ---------------------------- |
| 群系 | 草原 / 森林 / 山地 / 湖河        | 两个低频噪声查表             |
| 地形 | 地面高度                         | 按群系幅度的噪声，量化成台地 |
| 结构 | 教学城、城市入口、遗迹、颜料来源 | 大格子哈希                   |
| 细节 | 树、石、草、花                   | 哈希随机，按群系换表         |
| 派生 | 颜色、墨污浓度                   | 由城市状态实时算，不存       |

### 1.2 群系

```js
const relief = noise(seed, 'relief', x / 10, z / 10); // -1 平坦 … +1 陡峭
const moist = noise(seed, 'moist', x / 8, z / 8); // -1 干 … +1 湿
const water = ridged(seed, 'water', x / 14, z / 14); // 脊线噪声，接近 0 是河
```

| 条件           | 群系    | 地形幅度                        | 植被             | 墨污生物   | 颜料来源                     |
| -------------- | ------- | ------------------------------- | ---------------- | ---------- | ---------------------------- |
| `water < 0.05` | 河 / 湖 | 0，水面 y = -0.5                | 芦苇             | 少         | 湖面（蓝、青）               |
| `relief > 0.4` | 山地    | 高，台地 0.5 米一级，最高 24 米 | 稀疏松树、岩石   | 飞行型     | 矿脉（红、紫），山顶藏稀有色 |
| `moist > 0.2`  | 森林    | 低                              | 密集树，遮挡视线 | 多，近战型 | 花田（绿、黄）               |
| 其余           | 草原    | 很低                            | 零散树、草       | 少         | 花田（橙、粉）               |

教学城周围 3 个区块强制为草原（`relief`、`moist` 向 0 衰减），保证起点平缓。

### 1.3 地形：台地，不是平滑曲面

现有碰撞是 AABB 盒子 + 0.55 米自动上台阶，导航网格每格多层。因此地形不做高度场碰撞，而是**把噪声高度量化成 0.5 米一级的台地**，每级一排盒子：

```js
const h = amplitude(biome) * fbm(seed, 'height', x / 6, z / 6);
const level = Math.round(h / 0.5) * 0.5;
```

- 玩家自动走上 0.5 米台阶；1 米以上落差要跳或钩索。
- 盒子按行程压缩（同高度相邻格合并），一个 128 米区块的台地在几百个盒子以内。
- 等高线本来就是手绘地图的样子，台地比平滑地形更像画出来的。
- 导航网格直接复用，不用改。

区块边界：高度函数是全局的，相邻区块在共享边上算出的高度相同，不会出现断层。

### 1.4 结构：大格子哈希

Minecraft 村庄的做法：把世界分成大格子，每格用哈希决定有没有、放在格内哪个位置。

| 结构     | 格子                      | 规则                                                                                       |
| -------- | ------------------------- | ------------------------------------------------------------------------------------------ |
| 教学城   | 固定在原点                | 3×3 区块，模板写死                                                                         |
| 城市入口 | 每 7×7 区块一格           | 格内哈希选一个区块，避开水和陡坡；入口地标从模板库抽；城 ID = `hash(seed, 'city', gx, gz)` |
| 遗迹     | 每 4×4 区块一格，60% 概率 | 从遗迹模板抽，藏一支蜡笔；颜色按到原点距离分档                                             |
| 颜料来源 | 每区块 0–2 处             | 按群系从花田 / 矿脉 / 湖面抽，位置哈希                                                     |

城市入口的地标高 30–40 米，视距 2–3 个区块能看见，是"往那边走"的锚点。入口占一个区块，入口区块的地形强制平整。

### 1.5 远景剪影

视距外的区块不生成几何，只按群系层和结构层画一排纸面剪影：山的轮廓按高度噪声取样，森林是一排锯齿，地标用固定轮廓。噪声和哈希即时可算，不占存档。这是让世界"显得"大的关键。

### 1.6 派生状态

野外颜色和墨污浓度不存盘，每帧按附近城市的状态算：

```js
grey = max over nearby cities of (1 - progress(city)) * falloff(distance to city)
```

通关的城 `progress = 1`，周围恢复彩色；没进过的城 `progress = 0`，周围发灰、墨污生物密度高。玩家从山上回头看，画完的城周围是彩色的，这是通关最直观的奖励。

## 2. 城市副本

### 2.1 创建流程

进入一个入口地标第一次触发创建，房主执行，整座城一次算完落盘：

```text
1. 边界与城门：5×5 区块，入口地标所在边是正门，其余三边各 0–1 个侧门（哈希）
2. 道路生长（2.2）
3. 街块切分（2.3）
4. 街块填充：模板建筑先摆好，可玩（2.4）
5. AI 风格：城名、街区名、建筑参数、居民诉求（2.5），失败保留第 4 步结果
6. 区块状态初始化：所有表面置 0（抽色）；离正门近的区块据点弱，远的据点强
7. 落盘 world-data/<世界>/cities/<城ID>/
```

第 1–4 步在一秒内完成，玩家先进城；第 5 步在后台跑，完成后热更新名字和外观，不阻塞。

### 2.2 道路生长

城是有限的，可以全局求解，不受"区块独立可算"限制。用生长式算法得到弯曲、不等宽、有死胡同的老城：

```text
种子路：从正门和每个侧门各发一条主路，朝城中心方向
每步（4 米）：
  主路：方向加噪声扰动 ±8°，向中心轻微吸引
  碰到已有路（距离 < 6 米）：吸附接上，本条停止
  碰到边界：停止
  按密度概率分叉：主路每 24–40 米分一条次路（宽 6 米），次路每 16–30 米分一条小巷（宽 4 米）
  次路和小巷：转向幅度更大 ±20°，长度上限 60 / 30 米，可以成为死胡同
停止条件：所有路停止，或总长度超过上限
```

> **实现说明（2026-11-02）**：物理只有轴对齐盒子，所以道路在 4 米栅格上生长、只做直角转弯，长度和转弯点随机。看起来仍是自然生长的老城（错落的街角、丁字路口、死胡同），但建筑都能用盒子表示。代码见 `src/world/city/layout.ts`，参数在 `content/tuning.ts` 的 `city.roads`。

主路宽 10 米、次路 6 米、小巷 4 米。密度由城的"性格"决定（哈希得到：紧凑老城 / 疏朗新城），性格也进 AI 上下文。

生成后做一次清理：删除长度 < 12 米的孤立小巷；保证每个城门到中心连通（BFS），不通就补一条直路。

### 2.3 街块切分

道路两侧偏移半宽后，剩下的空地用扫描线切成多边形街块。不规则是预期效果：三角形广场、楔形街块都保留。每个街块记录：面积、边数、临哪条路、到中心距离。

- 面积 < 60 平方米：留空当广场或种树。
- 面积 > 1200 平方米：从中间再切一刀（加一条小巷）。
- 每个街块指定一栋"画室"候选（临主路、面积适中），每区块最终只保留一个。

### 2.4 街块填充

沿街块边放建筑：每条临路边按 10–16 米一个地块切分，地块进深 10–14 米，从**建筑模板**抽一个按地块尺寸实例化。模板的参数（层数、屋顶、立面、配色）由街块到中心的距离和城的性格决定范围，具体值哈希。街块内部空地放院子、掩体、楼梯和天桥（沿用现有结构规则）。

构建器给每个表面（墙面、门、屋顶、地面段）分配一个区块内稳定的编号，并记下它的**原色**。原色来自模板的默认配色；AI 风格到位后替换为 AI 的配色方案。原色写进骨架，之后不变。

这一步出来的城已经能玩：有路、有楼、有屋顶、有据点出生点、有可以修复的原色。

### 2.5 AI 风格

AI 的输入是程序已经定好的骨架，输出只是参数和文本：

```json
{
  "city": { "character": "紧凑老城", "gate": "north", "blocks": 25 },
  "block": {
    "id": 7,
    "district": "临主路",
    "distance": 1,
    "buildings": [{ "id": 0, "lot": [14, 12], "floors": [3, 6] }]
  },
  "neighbors": { "north": "墨海路", "west": null },
  "palette": [0, 3, 7, 9]
}
```

输出：街区名、每栋楼的模板参数（在给定范围内）、2–3 条居民诉求。校验器检查范围和枚举；任何一项不过就丢弃那一项，保留程序默认值，不重试整座城。

一座 5×5 的城约 25 次街区调用 + 1 次城名调用，比现在"每走一个区块一次"少得多，而且不在关键路径上。

### 2.6 落盘

```text
cities/<城ID>/
  meta.json        名字、性格、城门、创建时间、通关状态
  roads.json       道路折线与宽度
  blocks/<n>.json  街块多边形、建筑实例参数、表面原色、诉求
  state/<n>.json   区块状态、据点进度、表面状态字节数组（0 抽色 / 1 原色 / 2+n 涂鸦，补丁式）
  interiors/       按需生成的住宅室内，沿用现有缓存规则
```

骨架（roads、blocks）创建后不变；只有 `state/` 接受补丁。带版本和校验和，损坏拒绝加载。

## 3. 模板

地标、建筑、遗迹共用一套模板机制：参数全是枚举或有界范围，构建器对任何合法参数组合都能产出几何和碰撞。

```json
{
  "kind": "building",
  "name": "拱廊商铺",
  "params": {
    "floors": { "min": 2, "max": 5 },
    "roof": ["flat", "gable", "hip"],
    "facade": ["arch", "plain", "stripes"],
    "palette": { "count": 2 }
  }
}
```

- 内置库：地标 3（塔楼、钟楼、车站）、建筑 3（住宅、商铺、仓库）、遗迹 3（石圈、断桥、碑林）。
- 玩家库 `world-data/templates/`：AI 创意工坊输出的参数集，可导出交换。工坊是第二版。
- 抽取：按 `kind` 和尺寸约束过滤，哈希选一个，再在参数范围内哈希取值。同一位置重新生成得到同一结果。

## 4. 确定性与测试

- 野外：同一种子任意顺序生成相同区块；相邻区块共享边高度一致；结构格子哈希稳定。
- 城市：同一入口两次创建得到相同骨架（道路生长用哈希随机，不用 `Math.random`）；每个城门到中心连通；街块互不重叠；建筑不压路。
- 模板：参数空间内随机 1000 组全部可构建、碰撞盒不穿模。
- 以上全部在 `node --test` 里跑，不依赖 Three.js。

## 5. 落地顺序

1. 噪声与哈希工具 + 群系表 + 台地地形，先单群系跑通碰撞和导航
2. 结构格子：教学城、入口地标、遗迹、颜料来源
3. 远景剪影
4. 城市：道路生长 + 街块切分，先用方块占位
5. 模板机制 + 内置库，替换占位
6. AI 风格与诉求
7. 派生颜色与墨污浓度

前三步做完野外就能走；第 4–5 步做完城能玩；第 6 步才接 AI。

## 6. 不打算用的

- **波函数坍缩**：适合固定瓦片集，这里街块由道路切出来，形状不规则，瓦片不适用。
- **张量场道路（CityEngine 式）**：效果最好但实现重；生长式已经能出老城感，先用它。
- **平滑高度场碰撞**：要新写碰撞和导航，台地方案复用现有的，且更符合画风。
- **野外用 AI**：无限范围下费用不可控，且噪声已经够。
